# 毛春家庭积分

一个面向手机使用的家庭任务、积分、审核与愿望兑换工具。当前版本支持按真实月份记录、离线本机保存、PWA 安装，以及通过 Supabase 在三台或更多设备之间实时同步。

## 这次修复了什么

- 不再使用失效且没有权限保护的匿名公共 KV 房间。
- 本机先保存，断网操作进入待上传队列；联网后按唯一操作 ID 重试，避免重复计分。
- 服务端原子加减积分，Realtime 通知其他手机重新读取权威账本。
- 审核撤销、兑换撤销、清空当天和重置全部都能传播到其他设备。
- 页面刷新不再自动载入演示账本；存储失败会明确提示。
- 自动定位上海时区的今天，支持每月 28–31 天，不再固定为 2026 年 10 月 20 日。
- 兑换按月份扣分；数据库事务会重新核算个人余额和当月 3000 元家庭基金余额，避免两台手机同时兑换造成超额。
- 手机端改为底部导航、44px 触控按钮和更紧凑的今日流程。
- 增加 Web App manifest、Service Worker、安装图标与自动化测试。

## 首次配置云同步（只做一次）

没有配置云同步时，软件仍会在当前手机本机保存。要让三台手机实时一致：

1. 在 [Supabase](https://supabase.com/) 新建一个免费项目。
2. 打开项目的 **SQL Editor**，粘贴并完整运行 [`supabase/schema.sql`](supabase/schema.sql)。
3. 打开 **Authentication → Providers / Sign In → Anonymous**，启用匿名登录。
4. 在 **Project Settings → API** 复制：
   - Project URL
   - Publishable key（旧项目中可能显示为 `anon` key）
5. 编辑 [`config.js`](config.js)：

   ```js
   window.MAOCHUN_CONFIG = {
     supabaseUrl: 'https://你的项目.supabase.co',
     supabaseAnonKey: '你的 publishable 或 anon key'
   };
   ```

6. 提交并推送 `config.js`，等待 GitHub Pages 更新。

Publishable/anon key 设计上允许出现在网页前端；真正的权限由 `schema.sql` 中的 RLS 和只写 RPC 控制。**不要把 `service_role` key、数据库密码或个人访问令牌放进仓库。**

## 三台手机第一次使用

1. 第一台手机打开“同步”，选择“创建家庭账本”，填写使用者和设备名称。
2. 保存创建后显示的 36 位家庭邀请码。
3. 第二、第三台手机打开同一公开网址，在“同步”中粘贴邀请码并加入。
4. 页面顶部显示“所有设备数据已同步”后即可使用。任一手机打卡，其他手机通常会在 1–2 秒内更新。

匿名登录身份保存在当前浏览器中。若清除了浏览器数据，可用家庭邀请码重新加入。邀请码等同于家庭钥匙，请只私下分享。

## 从旧版迁移

如果旧手机还保留数据：先在旧页面的“设置”中导出 JSON；打开新版后在“设置”中导入。第一台手机创建家庭时，也会自动把当前本机账本作为初始数据上传。第二、第三台手机加入时不会上传各自的旧演示数据。

## 本地检查

```bash
npm test
npm run check
```

项目是纯静态网页，不需要构建。请通过 HTTP 服务器预览，不要直接双击 `index.html`，否则 Service Worker 与部分浏览器存储能力不会启用。

## 数据安全说明

- 数据库表全部启用 Row Level Security。
- 未登录访问者没有任何表权限。
- 已登录设备只能读取已加入家庭的数据。
- 前端不能直接写业务表，所有写入通过验证家庭成员身份的 RPC 完成。
- 每次操作使用 UUID 幂等收据；网络重试不会重复加分。
- 打卡行保存当时的单位分值；兑换在服务端加同月事务锁并原子校验余额。
- 单条无法修复的异常操作会被隔离提示，不会堵住后续打卡上传。
- 删除使用软删除/取消标记，避免旧手机把已删除数据恢复出来。
